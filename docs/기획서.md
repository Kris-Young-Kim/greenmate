시장 검증을 빠르게 하기 위한 MVP(최소 기능 제품) 단계에서, **'베란다 식집사를 위한 AI 육묘 가이드'라는 핵심 가치를 증명하기 위해 제가 정의한 '진짜 필수 기능'**은 다음과 같습니다.
💡 전문가가 제안하는 MVP 필수 기능 정의:
간편 식물 등록: 내가 키우는 식물(예: 고추, 상추 등)과 시작일 등록.
원클릭 물주기 기록: 복잡한 일지 대신 오늘 물을 줬는지 체크하는 단순 로그 기능.
식물 정보가 주입된 AI 채팅: 사용자가 굳이 "내가 키우는 고추가 어쩌고..." 설명하지 않아도, AI가 이미 내 식물의 종류와 일수를 알고 대답해 주는 1:1 상담 창.
이 3가지 에센셜(Essential) 기능만 남기고, 주니어 개발자가 Claude Code와 v0를 활용해 '바이브 코딩'으로 딱 한 달(4주) 만에 무조건 배포할 수 있는 초경량 MVP 기획서로 전면 재가공해 드립니다.
[초경량 MVP] 그린메이트 (GreenMate) 기획서
1. MVP 개발 목표
목표: "내 식물 정보를 기억하는 AI 비서가 있을 때 가드너들의 관리 지속성이 증가하는가?"를 최소 비용으로 검증.
개발 기간: 4주 (1인 개발 기준)
제외된 기능 (과감히 포기): 이미지 업로드(S3 연동 불필요), 푸시 알림 서버(정기 크론탭 불필요), 다중 대화 세션 관리, 커뮤니티, 정밀 생육 타임라인 그래픽.
2. 초경량 DB 스키마 설계 (Neon Postgres / Prisma)
주니어 개발자가 가장 많이 막히는 'Clerk 회원 정보 동기화 웹훅(Webhook)' 구현을 과감히 생략합니다. Clerk의 userId 스트링을 테이블에서 직접 외래키처럼 사용하여 테이블을 단 3개로 압축합니다.
code
Prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

// 1. 등록 식물 테이블
model Plant {
  id        String   @id @default(uuid())
  userId    String   // Clerk auth().userId를 직접 기록 (User 테이블 동기화 생략)
  nickname  String   // 식물 별명 (예: "베란다 상추")
  plantType String   // 작물 종류 (상추, 고추, 토마토 등)
  plantedAt DateTime // 키우기 시작한 날짜
  createdAt DateTime @default(now())

  waterings Watering[]
  chats     Chat[]
}

// 2. 물주기 기록 테이블 (기록용 단순 로그)
model Watering {
  id        String   @id @default(uuid())
  plantId   String
  plant     Plant    @relation(fields: [plantId], references: [id], onDelete: Cascade)
  wateredAt DateTime @default(now()) // 물 준 시간
}

// 3. 식물별 지속 대화 기록 (단일 스레드 구조)
model Chat {
  id        String   @id @default(uuid())
  plantId   String
  plant     Plant    @relation(fields: [plantId], references: [id], onDelete: Cascade)
  role      String   // "user" 또는 "assistant"
  content   String   // 대화 내용
  createdAt DateTime @default(now())
}
3. 화면 구성 및 UX 흐름 (단 2개의 Page로 끝내기)
v0로 구현 시 단 두 개의 URL 뷰(View)만 만들면 됩니다.
Page 1: 메인 대시보드 (/dashboard)
[식물 등록 모달]: 식물 종류 선택(드롭다운), 별명, 시작일 입력 끝.
[내 식물 리스트 카드]:
"상추 기른 지 +14일째 🌱"
[오늘 물주기 완료] 큰 버튼 하나 (클릭 시 DB에 바로 기록 후 날짜 갱신).
버튼 클릭 시 상세 대화방으로 이동.
Page 2: AI 상담실 (/plant/[id]/chat)
식물별 단일 채팅방 (카카오톡 스타일).
하단에 자주 묻는 질문 템플릿 버튼 배치 (예: "잎이 노래요", "물이 부족할 때 증상은?").
4. MVP 핵심 기능 구현 스펙
1) 식물 정보 주입 AI 대화 (Context-Aware Chat)
스펙: 사용자가 질문을 던질 때, 백엔드에서 해당 식물 정보(예: "상추, 키운 지 12일 됨, 물주기 기록 3회")를 읽어와 Claude API 시스템 프롬프트 헤더에 붙여 전송합니다.
작동 프롬프트 구조 예시 (Next.js Server Action):
code
TypeScript
const systemPrompt = `
너는 홈 가드닝 전문가야. 사용자가 키우는 식물 정보는 다음과 같아.
- 종류: ${plant.plantType}
- 별명: ${plant.nickname}
- 키운 지: ${diffDays}일째
- 최근 물준 날짜: ${lastWateredDate}
이 정보를 바탕으로, 사용자가 질문할 때 굳이 본인 식물 상황을 설명하지 않아도 맞춤형 답변을 해줘.
`;
2) 간이 물주기 트래커
스펙: 대시보드의 '물주기' 버튼을 누르면 오늘 날짜의 Watering 데이터가 추가됩니다. 대시보드에서는 "마지막으로 물 준 지 3일 전"과 같은 문구로 노출되어 직관성을 줍니다.
5. 주니어 개발자를 위한 4주 런칭 로드맵 (Claude Code 활용)
주니어 개발자가 Claude Code에게 순서대로 던질 명령 가이드입니다.
1주 차: 프로젝트 셋업 및 DB 이식
목표: Next.js, Clerk 로그인, Neon DB 연결.
Claude Code 명령어: "Prisma 스키마 파일 기준으로 Neon DB 마이그레이션 실행하고, Clerk 소셜 로그인 기본 템플릿 적용해줘."
2주 차: v0 UI 복사 및 대시보드 API 연결
목표: v0 대시보드 컴포넌트 이식 및 식물 등록/조회 기능 완성.
Claude Code 명령어: "v0 컴포넌트 코드를 기반으로, 사용자가 식물을 등록하면 Neon DB에 저장하고 리스트에 보여주는 Server Action 코드를 작성해줘."
3주 차: 물주기 기능 및 AI 채팅 엔드포인트 연동
목표: 오늘 물주기 버튼 및 Claude API를 활용한 컨텍스트 주입 채팅 기능 개발.
Claude Code 명령어: "Plant 테이블 정보와 마지막 Watering 날짜를 읽어와 Claude API 프롬프트에 주입하는 chat api route를 구현해줘."
4주 차: Vercel 배포 및 가벼운 QA
목표: Vercel에 배포하고 실기기로 동작 테스트 진행 및 버그 수정.
Claude Code 명령어: "Vercel 배포 시 발생한 빌드 에러 로그를 분석해서 해결해줘."
